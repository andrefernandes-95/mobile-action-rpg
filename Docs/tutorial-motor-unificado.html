Tutorial baseado no código real do projecto

Duas formas de andar.
Uma só classe.

O Player recebe uma direcção e move-se imediatamente com CharacterController. A AI recebe um destino e deixa o NavMeshAgent encontrar o caminho. O método IsPlayer() é o único interruptor.

01 · Diagnóstico

O que existe hoje?

O projecto usa o padrão Strategy: CharacterManager fala com a interface IMovementMotor, e em runtime escolhe uma de duas classes.

CharacterManagerpede Move, Stop ou SetDestination
→
IMovementMotorcontrato comum
→
CC / NavMeshduas implementações

Custo actual

3 ficheiros de movimento, referências duplicadas, activação/desactivação manual e métodos vazios para satisfazer a interface.

O que preservamos

Player preciso, AI com pathfinding, troca de personagem, dodge, animação, patrulha, chase e morte.

A interface não está “errada”. É uma boa escolha quando existem várias implementações independentes. Aqui, porém, as duas vivem sempre no mesmo tipo de personagem e trocam através de uma única regra global. Para este jogo, podemos pagar menos abstracção.

02 · Contrato actual

Nove membros, mas nem todos são comuns

MembroPlayerAI
MoveFunção principalQuase desnecessário
SetDestinationFica vazioFunção principal
StoppingDistanceDevolve sempre 0Valor real do Agent
RemainingDistance / HasPathValores falsosValores reais do Agent
Stop / ApplyDisplacementÚteisÚteis
Leitura importante: a interface unifica a forma de chamar, não o significado. Isto obriga o Player a fingir que conhece destinos e caminhos. A classe única pode manter a mesma API pública, mas assumir honestamente que alguns métodos pertencem apenas a um dos modos.
03 · Modelo mental

IsPlayer() funciona como uma prop

Pensa num componente React que recebe isPlayer. Se for verdadeiro, renderiza controlos manuais; se for falso, renderiza navegação automática. Em Unity não renderizamos UI — escolhemos o componente físico activo.

IsPlayer() == trueCC ligado · Agent desligado
Move(direction)
↔
IsPlayer() == falseCC desligado · Agent ligado
SetDestination(position)

A regra de ouro é: nunca deixar os dois componentes activos ao mesmo tempo. Caso contrário, ambos tentam escrever no mesmo Transform.

04 · Código final

A classe única: MovementMotor.cs

Este ficheiro substitui IMovementMotor.cs, CharacterControllerMotor.cs e NavMeshAgentMotor.cs. Não há herança de gameplay nem interface; só um MonoBehaviour com dois caminhos explícitos.

Assets/Scripts/Movement/MovementMotor.cs
using UnityEngine;
using UnityEngine.AI;

namespace AF
{
    [RequireComponent(typeof(CharacterController))]
    [RequireComponent(typeof(NavMeshAgent))]
    public sealed class MovementMotor : MonoBehaviour
    {
        [SerializeField] float runSpeed = 5.5f;
        [SerializeField] float gravity = -20f;

        CharacterManager character;
        CharacterController controller;
        NavMeshAgent agent;
        Vector3 velocity;
        bool motorEnabled = true;

        public float MoveAmount { get; private set; }
        public float RunSpeed => runSpeed;

        public Vector3 PlanarVelocity
        {
            get
            {
                if (character.IsPlayer())
                {
                    return new Vector3(velocity.x, 0f, velocity.z);
                }

                if (agent.enabled)
                {
                    Vector3 agentVelocity = agent.velocity;
                    agentVelocity.y = 0f;
                    return agentVelocity;
                }

                return Vector3.zero;
            }
        }

        public float StoppingDistance => character.IsPlayer() ? 0f : agent.stoppingDistance;
        public float RemainingDistance => agent.enabled ? agent.remainingDistance : 0f;
        public bool HasPath => agent.enabled && agent.hasPath;
        public bool IsMotorEnabled => motorEnabled;

        void Awake()
        {
            character = GetComponent<CharacterManager>();
            controller = GetComponent<CharacterController>();
            agent = GetComponent<NavMeshAgent>();
            agent.updateRotation = false;
        }

        void Start()
        {
            RefreshMode();
        }

        public void RefreshMode()
        {
            bool isPlayer = character.IsPlayer();

            if (agent.enabled && agent.isOnNavMesh)
            {
                agent.ResetPath();
            }

            controller.enabled = false;
            agent.enabled = false;

            if (motorEnabled && isPlayer)
            {
                controller.enabled = true;
            }
            else if (motorEnabled)
            {
                agent.enabled = true;
            }

            velocity = Vector3.zero;
            MoveAmount = 0f;
        }

        public void Move(Vector3 direction, float moveAmount)
        {
            if (!motorEnabled || !character.IsPlayer() || !controller.enabled)
            {
                return;
            }

            MoveAmount = Mathf.Clamp01(moveAmount);
            direction.y = 0f;

            if (direction.sqrMagnitude < 0.0001f || MoveAmount <= 0f)
            {
                Stop();
                return;
            }

            direction.Normalize();
            velocity.x = direction.x * runSpeed * MoveAmount;
            velocity.z = direction.z * runSpeed * MoveAmount;

            ApplyGravity();
            controller.Move(velocity * Time.deltaTime);
        }

        public void SetDestination(Vector3 worldPosition)
        {
            if (!motorEnabled || character.IsPlayer() || !agent.enabled || !agent.isOnNavMesh)
            {
                return;
            }

            MoveAmount = 1f;
            agent.speed = runSpeed;
            agent.SetDestination(worldPosition);
        }

        public void Stop()
        {
            MoveAmount = 0f;

            if (character.IsPlayer())
            {
                velocity.x = 0f;
                velocity.z = 0f;

                if (motorEnabled && controller.enabled)
                {
                    ApplyGravity();
                    controller.Move(new Vector3(0f, velocity.y, 0f) * Time.deltaTime);
                }

                return;
            }

            if (agent.enabled && agent.isOnNavMesh)
            {
                agent.ResetPath();
                agent.velocity = Vector3.zero;
            }
        }

        public void ApplyDisplacement(Vector3 worldDelta)
        {
            if (!motorEnabled)
            {
                return;
            }

            if (character.IsPlayer())
            {
                controller.Move(worldDelta);
                return;
            }

            agent.Move(worldDelta);
        }

        public void SetMotorEnabled(bool enabled)
        {
            motorEnabled = enabled;

            if (!enabled)
            {
                velocity = Vector3.zero;
                MoveAmount = 0f;
            }

            RefreshMode();
        }

        void ApplyGravity()
        {
            if (controller.isGrounded && velocity.y < 0f)
            {
                velocity.y = -2f;
            }
            else
            {
                velocity.y += gravity * Time.deltaTime;
            }
        }
    }
}
Porque não guardamos o último destino? Para máxima simplicidade. Chamar SetDestination em cada frame de chase é normal. A optimização antiga de 0,15 pode voltar apenas se o Profiler provar que faz falta.
05 · Integração

Simplificar o CharacterManager

O manager deixa de descobrir duas estratégias. Passa a ter uma única referência concreta.

1. Substituir os campos

CharacterManager.cs · campos
[Header("Movement")]
[SerializeField] MovementMotor motor;

public MovementMotor Motor => motor;

2. Simplificar Awake

CharacterManager.cs · Awake
void Awake()
{
    defaultPosition = transform.position;

    if (motor == null)
    {
        motor = GetComponent<MovementMotor>();
    }
}

3. Substituir a troca de motores

CharacterManager.cs · controlo
public void GiveControlToAI()
{
    motor.RefreshMode();
}

public void GiveControlToPlayer()
{
    GameContext.SetPlayer(this);
    motor.RefreshMode();
}

Todo o resto de CharacterManager pode permanecer igual: Move, SetDestination, Stop, rotação, animação, dodge e morte continuam a chamar a mesma API.

Apaga do manager: os campos CharacterControllerMotor e NavMeshAgentMotor, SetupMotor(), UseCharacterControllerMotor() e UseNavMeshMotor().
06 · Detalhe crítico

A ordem da troca importa

No código actual, a personagem antiga recebe AI antes de GameContext.Player mudar. Mas o novo motor decide tudo consultando IsPlayer(). Portanto, primeiro mudamos o Player global; só depois refrescamos a personagem anterior.

PlayerInput.cs · SetCharacter completo
void SetCharacter(CharacterManager character)
{
    CharacterManager previousCharacter = characterManager;

    characterManager = character;
    characterManager.GiveControlToPlayer();

    if (previousCharacter != null && previousCharacter != characterManager)
    {
        previousCharacter.GiveControlToAI();
    }

    onSetCurrentCharacter?.Invoke(characterManager);
}

Sequência: a nova personagem torna-se Player → o seu motor liga o CC → a anterior já responde false a IsPlayer() → o seu motor liga o Agent.

07 · Aplicação

Passo a passo no Unity

  1. Criar MovementMotor.cs
    Cola a classe completa apresentada acima.
  2. Alterar CharacterManager.cs
    Troca os campos, simplifica Awake, troca os dois métodos de controlo e remove os métodos antigos.
  3. Alterar PlayerInput.SetCharacter
    Usa a ordem segura apresentada acima.
  4. Actualizar todos os prefabs
    Remove CharacterControllerMotor e NavMeshAgentMotor. Adiciona MovementMotor. Os componentes CharacterController e NavMeshAgent ficam presentes.
  5. Atribuir a referência
    Arrasta o MovementMotor para o campo Motor do CharacterManager, ou deixa Awake encontrá-lo.
  6. Apagar os ficheiros antigos
    Só depois de os prefabs e o manager compilarem: IMovementMotor.cs, CharacterControllerMotor.cs e NavMeshAgentMotor.cs.
Unity e referências perdidas: remover scripts dos prefabs antes de apagar os ficheiros evita componentes “Missing Script”. Faz a migração num prefab de teste primeiro.

Pergunta de engenharia

Porque é perigoso executar previousCharacter.GiveControlToAI() antes de alterar GameContext.Player?

Ver resposta

Porque previousCharacter.IsPlayer() ainda devolve true. O motor voltaria a ligar o CharacterController em vez do NavMeshAgent.

09 · Decisão consciente

O que ganhamos — e o que aceitamos

Ganhamos

Uma classe, uma referência, uma regra de escolha, menos setup e fluxo muito mais fácil de seguir no Inspector e no debugger.

Aceitamos

Todos os personagens têm CC e Agent; a classe conhece ambos; adicionar um terceiro motor exigirá novos if.

Para o estado actual do projecto, este compromisso é razoável: existem exactamente dois modos e ambos pertencem ao mesmo personagem. Se um dia aparecer voo, natação, veículo e multiplayer, a interface volta a ganhar valor. Não construímos hoje a arquitectura de um problema que ainda não existe.

Versão mínima da regra: Move só trabalha para Player. SetDestination só trabalha para AI. Stop e ApplyDisplacement escolhem o componente através de IsPlayer().
